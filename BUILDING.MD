# BUILDING.MD

## Requirements

- Microsoft Visual Studio 2022 (v143 toolset)
- Desktop development with C++ workload installed
- Windows 10 SDK
- The Major BBS v10 SDK

## Environment Setup

Before building, set the `MBBSSDKDIR` environment variable to point to your local
installation of the MBBS v10 SDK. The path must end with a backslash.

**System environment variable (recommended):**

```
MBBSSDKDIR=C:\path\to\mbbs-v10-sdk\
```

The SDK is available at: https://github.com/TheMajorBBS/MBBS-v10-module-SDK

After setting the environment variable, restart Visual Studio.

## Build Instructions

1. Open `DIALHOT.sln` in Visual Studio 2022.
2. Select the **Release | Win32** configuration.
3. Build the solution (F7 or Build > Build Solution).
4. The compiled `DIALHOT.DLL` will be placed in `BUILD\Release\`.

## Configurations

| Configuration | Platform | Output |
|---|---|---|
| Debug | Win32 | `BUILD\Debug\DIALHOT.DLL` |
| Release | Win32 | `BUILD\Release\DIALHOT.DLL` |

**Only Win32 (x86) is supported.** The MBBS v10 server process is 32-bit.

## Preprocessor Definitions

The project defines the following for all configurations:

| Definition | Purpose |
|---|---|
| `WIN32` | Windows platform |
| `GCWINNT` | Galacticomm Windows NT target |
| `GCMVC` | Galacticomm MSVC compiler target |
| `WGNT` | Worldgroup NT code path; required for the MBBS v10 NT module build target |
| `BBSVER=1000` | Target MBBS version 10 |
| `USE_DEF_FILE` | Use module definition file for exports |
| `__BUILDV10MODULE` | Building an MBBS v10 module |

## Struct Member Alignment

The project uses **8-byte struct alignment** (`/Zp8`) to match MBBS server expectations.
This must not be changed without consulting the MBBS v10 SDK documentation.

**Exception — `configrec`:** This module-defined struct stores its data in the Btrieve NOMSG record. The original Borland build used 1-byte (tight) packing. `HOT.H` wraps `configrec` with `#pragma pack(push,1)` / `#pragma pack(pop)` so `sizeof(configrec) == 1024`, matching the on-disk layout. Do not remove these pragmas.

## Char Signedness

The project uses `/J` (unsigned char by default) to match Borland-era behavior.
This is required for correct behavior of character comparison and ANSI code processing.

## Compiler Compatibility Notes

`RETVAL` and `FINRET` are Borland-era types not defined in the MBBS v10 SDK. HOT.H
defines them as type aliases (`RETVAL` → `GBOOL`, `FINRET` → `SHORT`) so HOT.C
compiles without modification. Both will be removed along with the licensing code
during the open-source transition.

The Windows SDK header `nb30.h` defines `REGISTERED` as a NetBIOS protocol constant.
HOT.H undefines it after the system includes so the module's own flag definition
takes precedence. This will also be removed with the licensing code.

## Message File

`DIALHOT.MSG` is the human-readable message source file. The BBS compiles this to
`DIALHOT.MCV` at startup. Do not commit `DIALHOT.MCV` to the repository; it is
generated by the BBS server.

The message number constants in `DIALHOT.H` must stay in sync with the order of
named messages in `DIALHOT.MSG`. The MBBS v10 MSG compiler assigns a number to
every named entry in the file including `LEVEL` section markers; the original
Borland `wgsmsx` compiler did not. `DIALHOT.MSG` contains a `LEVEL99` entry
between `PKEYFTR` and `CNF12`, so `CNF12`, `CNF21`, and `CNF30` are each one
higher than the values the original `wgsmsx`-generated header used.

## Release Packaging

After a successful Release build:

1. Copy `BUILD\Release\DIALHOT.DLL` to `DIST\<version>\DIALHOT.DLL`
2. Copy `SRC\DIALHOT.MDF` to `DIST\<version>\DIALHOT.MDF`
3. Copy `SRC\DIALHOT.MSG` to `DIST\<version>\DIALHOT.MSG`
4. Copy `SRC\DIALHOT.DAT` to `DIST\<version>\DIALHOT.DAT`
5. Copy `SRC\DIALHOT.VIR` to `DIST\<version>\DIALHOT.VIR`

All filenames in DIST must be uppercase.

`DIALHOT.BCR` is kept in `SRC\` as a reference document describing the Btrieve
database structure but is not included in the distribution. The `.DAT` file is the
actual deployable Btrieve database.
